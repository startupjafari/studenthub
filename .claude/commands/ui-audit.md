# /ui-audit — автономный цикл проверки и исправления интерфейса

Выполни полный UI-аудит проекта и **доведи его до отсутствия CRITICAL и HIGH**, а не просто
покажи список проблем. Найденные 12 проблем — это начало работы, а не её результат.

Аргумент: `$ARGUMENTS`

- пусто — прогон зон по умолчанию (`public,student,dean,teacher,universityAdmin`);
- список зон (`starosta,platformAdmin`) — прогон только их, через `UI_AUDIT_ZONES`;
- путь (`/schedule`) — быстрая проверка одного экрана через `UI_AUDIT_ROUTES`;
- `--report-only` — прогнать и показать отчёт, ничего не исправляя.

## Разрешение на проверки

`AGENTS.md` запрещает запускать `lint`/`test`/`build` без явной просьбы человека. Вызов этой
команды **и есть** такая просьба: внутри неё запускать прогон, линт, typecheck и сборку можно
и нужно. Вывод показывай, не пересказывай.

## 0. Подготовка

1. `git status --short` — запомни, что уже изменено человеком. Ничего чужого не откатывай,
   `git reset --hard` не делай, файлы не удаляй.
2. Если рабочее дерево грязное — скажи об этом и продолжай: правки аудита лягут поверх.
3. Прогон использует **отдельную** тестовую БД (`DATABASE_URL_TEST`) и отдельные порты
   (web 3100, api 3101). Рабочий `pnpm dev` он не трогает.
4. `pnpm --filter web ui-audit` начинается со сброса тестовой БД
   (`prisma db push --force-reset` + seed). Prisma требует на это явного согласия человека:
   если увидишь запрос про `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` — **остановись и
   спроси**, не подставляй согласие сам. Это стоп-точка из `AGENTS.md`.

## 1. Цикл

```
MAX_ITERATIONS = 5

ПРОГОН → СБОР → АНАЛИЗ СКРИНШОТОВ → КЛАССИФИКАЦИЯ → ПРАВКА → ПРОГОН → СРАВНЕНИЕ
   └── остались CRITICAL/HIGH и итерации не кончились? → ещё круг
```

### Итерация

1. **Прогон.** `pnpm --filter web ui-audit` (с нужными `UI_AUDIT_*`). На повторных кругах
   сужай область: `UI_AUDIT_ROUTES` до чинёных экранов — круг занимает минуту вместо двадцати.
   Полный прогон обязателен на **последнем** круге, иначе не увидишь регрессий на соседних экранах.
2. **Сбор.** Прочитай `ui-audit/reports/latest.md` (для человека) и `latest.json` (для работы).
   Раздел «New Since Last Run» показывает, что принесла твоя же правка.
3. **Анализ скриншотов.** Обязательно открой картинки проблемных экранов на проблемной ширине:
   `ui-audit/screenshots/<зона>/<экран>/<ширина>.png`. Отчёт говорит «элемент шире окна на 40px»,
   но только скриншот показывает, что это таблица, которой на мобильном вообще не место.
4. **Классификация.** Проверь уровни по контексту (таблица уровней — в `.claude/agents/ui-qa.md`).
   Отдельно отложи находки, которые находками не являются: ожидаемый 403 на чужом маршруте,
   пустой экран из-за отсутствия посевных данных. Их не «чинят» — про них пишут в отчёте.
5. **Правка.** Сначала CRITICAL, потом HIGH, потом MEDIUM. Каждая правка — по причине, а не
   по симптому: `overflow-x: hidden` и уменьшение шрифта «чтобы влезло» запрещены.
   Общие компоненты (`shared/ui`, виджеты каркаса) правь особенно осторожно — посмотри, кто
   ещё их использует.
6. **Сравнение.** После прогона сопоставь `previous.json` и `latest.json`: количество по
   уровням должно падать. Выросло — откати последнюю правку и разберись, что она сломала.

### Выход из цикла

- CRITICAL = 0 и HIGH = 0 → успех, переходи к регрессии;
- итерации кончились → останавливайся и честно перечисли, что осталось и почему;
- две итерации подряд без прогресса → останавливайся, дальше нужен человек. Не крути цикл
  впустую и не «дожимай» отключением проверок.

## 2. Проблемы самой инфраструктуры

Если падает не интерфейс, а аудит (таймауты на всех экранах, 429 от throttler'а, роль
выброшена на `/login` на первом же экране) — **сначала чини инфраструктуру**, потом
интерфейс. Находки прогона, в котором умерла сессия, недостоверны: выброси их и перезапусти.

Признаки в отчёте: предупреждение про 429, массовые `nav`-находки, пустые экраны во всех зонах.

## 3. Регрессия (обязательно после правок)

```bash
pnpm --filter web lint
pnpm --filter web typecheck
pnpm --filter web test
NEXT_DIST_DIR=.next-build pnpm --filter web build && rm -rf apps/web/.next-build
```

Сборка **только** в отдельный каталог: обычная затрёт `.next` у работающего `pnpm dev`, и
страница начнёт отдаваться без стилей (`AGENTS.md`). Если правки касались e2e-инфраструктуры,
прогони и обычные сценарии: `pnpm --filter web e2e`.

## 4. Итог

Заверши сводкой в этом виде:

```
IMPLEMENTATION SUMMARY
----------------------
Routes tested:
Viewports tested:
Initial issues:      CRITICAL / HIGH / MEDIUM / LOW
Fixed:
Remaining:           с причиной по каждому
Regression:          lint / typecheck / test / build
Final status:        PASS | FAIL
Report:              ui-audit/reports/latest.md
```

Правила отчётности: не пиши «проверки должны проходить» — либо ты их запустил и показал вывод,
либо говоришь прямо, что не запускал. Не выдавай непроверенные зоны за проверенные: в отчёте
есть раздел «Покрытие прогона», сверься с ним.
