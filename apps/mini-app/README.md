# StudentHub — Telegram Mini App (`apps/mini-app`)

Мини-апп **для администраторов и модераторов платформы**: очередь жалоб в кармане. Vite +
React + TypeScript, отдельное приложение монорепо рядом с `web`, `api` и `landing`.

Студентам он не адресован: `PLATFORM_ADMIN` и `PLATFORM_MODERATOR` — единственные роли,
которым сервер выдаёт сессию.

## Запуск

```bash
pnpm install                        # из корня монорепо
pnpm --filter mini-app dev          # http://localhost:3003
```

`pnpm dev` в корне поднимает его вместе с остальными приложениями (web 3000, api 3001,
landing 3002, mini-app 3003).

Нужен и работающий API: адрес задаётся в `.env.local` (образец — `.env.example`), по
умолчанию `/api/v1` того же origin.

```bash
cp apps/mini-app/.env.example apps/mini-app/.env.local
```

В обычном браузере открывается экран «Откройте из Telegram»: очередь жалоб требует подписи
`initData`, которой вне клиента нет. Это не заглушка «на потом», а честный ответ — токен
выдаётся только за подпись.

## Проверка в Telegram

Telegram открывает только https, поэтому dev-сервер выставляется наружу туннелем. Бесплатный
туннель живёт минутами и при каждом переподключении выдаёт **новый** адрес — вписывать его в
бота руками бессмысленно. Этим занимается скрипт:

```bash
echo 'TELEGRAM_BOT_TOKEN=<токен от @BotFather>' > apps/mini-app/.env.local
pnpm --filter mini-app dev          # терминал 1
pnpm --filter mini-app tunnel       # терминал 2
```

Скрипт держит туннель, ловит выданный адрес и сам прописывает его в кнопку меню бота
(`setChatMenuButton`). Оборвалось — поднимается заново и прописывает новый адрес. В чате
с ботом кнопка всегда ведёт на живой.

`.env.local` в git не попадает (корневой `.gitignore`). Токен — секрет, в репозиторий его
класть нельзя.

Про выбор туннеля: `cloudflared` требует исходящий порт 7844, который во многих сетях закрыт,
а `pinggy` и `serveo` показывают браузеру страницу-предупреждение — переход по её кнопке
теряет фрагмент адреса, а вместе с ним `initData`. Поэтому в скрипте `localhost.run`.

## Сборка

```bash
pnpm --filter mini-app build        # → dist/
pnpm --filter mini-app typecheck
```

`base: './'` в [vite.config.ts](vite.config.ts) — статика раздаётся с любого пути, не
обязательно из корня домена.

## Что внутри

| Файл                                                         | Зачем                                                                                                 |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| [src/telegram/webapp.ts](src/telegram/webapp.ts)             | Единственная точка доступа к `window.Telegram.WebApp`, перенос темы клиента в CSS-переменные, хаптика |
| [src/telegram/types.ts](src/telegram/types.ts)               | Типы ровно на используемую часть API — вместо пакета-обёртки                                          |
| [src/telegram/use-telegram.ts](src/telegram/use-telegram.ts) | Хуки над `BackButton` и `MainButton`                                                                  |
| [src/app.tsx](src/app.tsx)                                   | Три исхода старта: вне Telegram, привязка, очередь                                                    |
| [src/api/client.ts](src/api/client.ts)                       | Сессия по initData, токен в памяти, повтор запроса после истечения                                    |
| [src/api/complaints.ts](src/api/complaints.ts)               | Очередь жалоб: типы по ответу `GET /complaints`                                                       |
| [src/screens/link.tsx](src/screens/link.tsx)                 | Ввод кода привязки, выданного в веб-версии                                                            |
| [src/screens/complaints.tsx](src/screens/complaints.tsx)     | Очередь модерации: порядок задаёт сервер                                                              |
| [scripts/tg-tunnel.mjs](scripts/tg-tunnel.mjs)               | Туннель для проверки в Telegram + перерегистрация кнопки бота                                         |

Решения, которые стоит знать до правок:

- **SDK подключается тегом из `index.html`, а не пакетом.** Библиотека обязана быть готова
  до первого рендера, и Telegram обновляет её вместе с клиентом; локальная копия устаревает.
- **Всё работает вне Telegram.** `webApp()` возвращает `null`, обёртки молчат. Иначе отладка
  превращается в «проверяй только с телефона».
- **Цвета — только через `--tg-theme-*`.** Клиент меняет тему на лету; своя палитра сразу
  разъедется с окружением.
- **`onClick` у кнопок Telegram добавляет обработчик, а не заменяет.** Снятие обязательно,
  иначе после нескольких переходов один тап вызовет несколько колбэков — этим занимаются
  хуки в `use-telegram.ts`.
- **Токен живёт только в памяти.** Ни `localStorage`, ни cookie: встроенный браузер общий
  для всех мини-аппов клиента, а токен даёт админский доступ. Истёк — берём новый по
  свежему `initData`, повтор запроса ровно один.
- **Отказ сессии не означает «не привязан».** Сервер одинаково отвечает и на отсутствие
  привязки, и на снятую роль — иначе по разнице ответов вычислялось бы, кто из админов
  привязан. Поэтому после отказа показывается экран привязки: это единственное действие,
  которое может помочь.
