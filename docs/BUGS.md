# Журнал багов

Найденные дефекты StudentHub по ролям и на стыках ролей. Не план задач и не бэклог фич: сюда
попадает только то, что работает **не так, как задумано** по `docs/PROJECT.md` (контракты,
матрица доступа) и правилам `docs/BACKEND_RULES.md` / `docs/FRONTEND_RULES.md`.

## Как вести

- Один баг — одна запись `BUG-NNN`, номер не переиспользуется.
- Исправлен — статус `исправлен` и ветка/PR; не баг — `отклонён` с причиной. Записи не удаляются.
- Сначала самые серьёзные. Безопасность и утечки данных — всегда отдельной пометкой 🔒.

**Серьёзность**

| Уровень | Что это |
|---|---|
| 🔴 Критический | Утечка данных, обход прав или scope, потеря данных, падение ключевого сценария |
| 🟠 Высокий | Сценарий роли не выполняется или выполняется неверно, обходного пути нет |
| 🟡 Средний | Неверное поведение с обходным путём, неверные данные на экране |
| 🟢 Низкий | Мелочь: текст, i18n, вёрстка, неочевидное поведение |

**Статусы:** `новый` → `подтверждён` → `в работе` → `исправлен` · `отклонён`

`подтверждён` — путь по коду перепроверен при составлении журнала; `новый` — найден статическим
разбором, по коду прослежен, но вторым человеком не перепроверен.

## Проход 1 — по ролям (23.10.2026)

### 🟠 Высокие

#### BUG-001 · 🟠 🔒 Студент читает дисциплины любой группы любого вуза через `GET /courses?groupId=`
- **Роль:** STUDENT, STAROSTA · **Статус:** подтверждён
- **Где:** `apps/api/src/modules/courses/courses.service.ts:332-334`
- **Сценарий:** у студента scope — `{ groupId: viewer.groupId }`, фильтр запроса подмешивается
  тем же spread и перезаписывает ключ. `GET /courses?groupId=<чужая группа>` отдаёт предметы,
  семестры и ФИО преподавателей чужой группы, в том числе другого вуза.
- **Ожидается:** фильтр сужает scope, а не подменяет — `AND: [scope, filters]` (BACKEND_RULES
  §6, §14.10; PROJECT §8.3 «студент — своя группа»).

#### BUG-002 · 🟠 🔒 Коды учебного статуса `EXPELLED`/`GRADUATED` не распознаются: охрана пропускает отчисленных, библиотека выдаёт им книги
- **Роль:** SECURITY_GUARD, LIBRARIAN · **Статус:** подтверждён
- **Где:** `apps/api/src/modules/users/academic-status.ts:6`, `apps/api/src/modules/library/library-loans.service.ts:53`, `apps/api/src/modules/student-id/student-id.service.ts:157`
- **Сценарий:** сервер сверяет только русские строки («отчислен», «выпускник», «переведён»), а
  сид (`prisma/seed/data/people.mjs:53`) и контракт API хранят коды. Студент с `EXPELLED` у
  охраны получает «Пропустить», у библиотекаря — `canBorrow: true`; `leftUniversityAt` не
  ставится, сроки хранения ПДн не начинают течь.
- **Ожидается:** отказ `STATUS` на входе (§3.12), `409 status` при выдаче и брони (§3.11) для
  любого представления статуса. Корень — два представления одного поля: веб пишет строки
  `ACADEMIC_STATUS_DICT`, сид и контракт — коды.

#### BUG-003 · 🟠 Ночная уборка удаляет утерянные книги с непогашенным долгом — долг пропадает
- **Роль:** LIBRARIAN → STUDENT · **Статус:** подтверждён
- **Где:** `apps/api/src/modules/cleanup/pd-retention.service.ts:114`
- **Сценарий:** `markLost` ставит `LOST` и `returnedAt`, `lostSettledAt` пуст. Через год
  `purgeClosedLoans` удаляет её по `status IN (RETURNED, LOST) AND returnedAt < cutoff`, не глядя
  на погашение. Справка «задолженностей нет» становится чистой, выдача снова открыта.
- **Ожидается:** долг остаётся до «Долг погашен» (§3.11); «открытые выдачи (долг) не удаляются
  никогда» (PERSONAL_DATA §4). Удалять `LOST` только при `lostSettledAt IS NOT NULL`, срок — от
  погашения.

#### BUG-004 · 🟠 🔒 Модератор вуза получает аналитику по студентам поимённо, хотя по матрице аналитика ему закрыта

- **Ожидается:** §2.2 «Аналитика — Мод. вуза ❌»; §8.3 «агрегаты (декан/админ вуза)». Убрать

#### BUG-005 · 🟠 Админ вуза в вебе не видит модераторов, охрану, библиотекарей и старост своего вуза

#### BUG-069 · 🟠 🔒 Refresh во время «гашения всех сессий» выдаёт токен, который это гашение переживает
