## 1. Стек: что разрешено

| Задача | Разрешено | Запрещено |
|---|---|---|
| Роутинг | Next.js App Router + route groups | Pages Router, ручной клиентский роутер |
| Стили | Tailwind CSS, `shadcn/ui`, `cn()` | Другие UI-киты, CSS-in-JS, inline-стили (кроме динамических значений) |
| Глобальное состояние | Redux Toolkit (`auth`, `ui`) | Zustand/MobX/Context как глобальный стор |
| Серверное состояние | TanStack Query (React Query) | `useEffect` + `fetch`, хранение серверных данных в Redux |
| Формы | React Hook Form + Zod из `shared-schemas` | Неконтролируемые формы без валидации, `<form action>` |
| HTTP | axios-инстанс из `shared/api` | `fetch()` в компонентах, второй axios-инстанс |
| Realtime | `socket.io-client` через единый провайдер | Несколько сокет-соединений, polling |
| Иконки | `lucide-react` | Прочие наборы, SVG-инлайн копипастой |
| Даты | `date-fns` + локаль | `moment`, ручное форматирование строк |
| Графики | `recharts` через `next/dynamic`, набор в `shared/ui/chart` | Синхронный импорт чартов, второй чарт-движок, своя обёртка вместо `shared/ui/chart` |
| i18n | `next-intl` | Хардкод строк в JSX |
| PWA | `@ducanh2912/next-pwa` | Ручной service worker |

**Категорически запрещено:** `localStorage` / `sessionStorage` для токенов и любых данных сессии.

### 1.1 shadcn/ui — практическая настройка (как есть в проекте)

- **CLI:** `pnpm dlx shadcn@latest add <компонент>` (cwd `apps/web`). Компоненты пишутся в `src/shared/ui/` (не в `shared/components/ui`) — так задано в `components.json` (`aliases.ui = "shared/ui"`, `aliases.utils = "shared/lib/utils"`). Стиль `radix-nova`, base-color `neutral`, Tailwind v4, CSS-переменные.
- **`cn()`** живёт в `src/shared/lib/utils.ts` (конвенция shadcn). Отдельного `lib/cn.ts` нет.
- **Тема** — в `src/app/globals.css`: `@import "tailwindcss"` + `tw-animate-css` + `shadcn/tailwind.css`, токены в `oklch` (`:root` / `.dark`), маппинг `@theme inline`. Тёмная тема через класс `.dark`. Новые цвета не хардкодить — использовать токены (`bg-card`, `text-muted-foreground`, `border-input`, `text-destructive`, …).
- **Зависимости shadcn-стека:** `radix-ui` (унифицированный пакет — импорт `import { Slot } from "radix-ui"`), `sonner` + `next-themes` (тосты, `<Toaster/>` в root layout), `tw-animate-css`, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react`.
- **Пути:** в `apps/web/tsconfig.json` добавлены `paths` для FSD-алиасов (`shared/*`, `entities/*`, `features/*`, `widgets/*`, `views/*`) — нужны, чтобы shadcn CLI резолвил алиасы. Импорты в коде — относительные или через эти алиасы.
- **Компонент `form`** из реестра `radix-nova` не ставится — формы собираем из `Label` + `Input` + `Button` + React Hook Form (`register`/`handleSubmit`), ошибки под полями через `text-destructive`.
- **Шрифт:** пресет `nova` тянет `Geist` из Google Fonts (`next/font/google`) — убрано ради offline-сборки, используется системный sans. Для брендового шрифта подключать `next/font/local` с локальными файлами.

## 2. Структура (Feature-Sliced Design)

```
apps/web/src/
├── app/                        # Next.js App Router: только роутинг, layout, loading, error
│   ├── (auth)/                 # /login, /register?token=
│   ├── (platform-admin)/       ├── (university-admin)/
│   ├── (moderator)/            ├── (dean)/
│   ├── (teacher)/              ├── (starosta)/
│   └── (student)/              # / — главная лента
├── shared/                     # Слой 1
│   ├── api/                    # axios instance, interceptors, socket-провайдер
│   ├── ui/                     # shadcn/ui компоненты
│   ├── lib/                    # cn(), формат дат, хелперы
│   └── config/                 # ROLE_HOME, NAV_BY_ROLE, env-константы
├── entities/                   # Слой 2: бизнес-сущности (модель + API-хуки + карточка)
│   ├── user/ university/ faculty/ group/
│   └── schedule/ post/ story/ event/ chat/ application/ notification/
├── features/                   # Слой 3: одно действие = одна фича
│   ├── auth-invite/ create-post/ send-message/ create-invite/
│   └── manage-schedule/ submit-application/ transition-application-status/
├── widgets/                    # Слой 4: составные блоки
│   ├── feed-list/ chat-window/ schedule-grid/ user-profile/
│   └── app-sidebar/ notifications-bell/ stats-dashboard/
└── pages/                      # Слой 5: композиция экрана, вызывается из app/**/page.tsx
```

### 2.1 Правило импортов FSD (нарушение = блокирующее замечание)

```
app → pages → widgets → features → entities → shared
```

Слой импортирует только слои **ниже**. Дополнительно:

- Импорт между слайсами одного слоя запрещён (`features/create-post` не импортирует `features/send-message`). Общее выносится в `entities` или `shared`.
- Внутри слайса — импорт только через публичный API `index.ts`. `import { X } from 'entities/post/ui/post-card'` — запрещено; `import { PostCard } from 'entities/post'` — правильно.
- `shared` не знает о доменной логике. `shared/ui/Button` не может импортировать `entities/user`.

### 2.2 Что лежит в `app/`

Только: `page.tsx` (тонкая обёртка над `pages/`), `layout.tsx`, `loading.tsx`, `error.tsx`, `not-found.tsx`, `middleware.ts`. Бизнес-логика и вёрстка в `app/` не пишутся.

Каждый route segment обязан иметь `loading.tsx` и `error.tsx`.

## 3. Ролевой роутинг и доступ

- Ролевой редирект решается в `middleware.ts` **до** рендера: читается refresh-cookie, определяется роль, применяется `ROLE_HOME[role]`. Флеш неавторизованного контента недопустим.
- `ROLE_HOME` и карта доступа маршрутов живут в `shared/config/routes.ts` и импортируют `Role` из `packages/shared-types`. Строковые литералы ролей в компонентах запрещены.
- Каждый route group имеет layout, проверяющий роль. Студент, открывший `/dean/...`, получает 403-экран, а не пустую страницу.
- **UI-скрытие — не защита.** Скрытая кнопка не отменяет необходимости серверной проверки; но и наоборот: элемент, недоступный роли по матрице доступа, не рендерится.
- Матрица доступа (`docs/PROJECT.md`) — единственный источник истины по тому, что видит роль. Расхождение UI с матрицей — баг.

## 4. Server / Client Components

- Server Component по умолчанию. `'use client'` добавляется **только** при наличии состояния, эффектов, обработчиков событий или браузерных API.
- `'use client'` ставится максимально глубоко в дереве: интерактивной делается кнопка, не вся страница.
- Персональные данные, которые можно получить на сервере, получаются на сервере. Загрузка первого экрана клиентским запросом — антипаттерн.
- Тяжёлые компоненты (чарты, редакторы, карты, WYSIWYG) — только через `next/dynamic` с `ssr: false` и скелетоном.
- Компоненты, читающие Redux или socket, всегда клиентские; выносить их в отдельные файлы, чтобы не делать клиентским весь экран.

## 5. Работа с API

### 5.1 Единственная точка входа

Все запросы идут через `shared/api/instance.ts`. `fetch()` или `axios.create()` в компонентах, `entities` или `features` — запрещены.

```ts
// shared/api/instance.ts
const api = axios.create({
  baseURL: process.env.NEXT_PUBLIC_API_URL,
  withCredentials: true,   // обязательно: refresh в httpOnly cookie
})
```

### 5.2 Обёртка ответа

Бэкенд отвечает `{ success, data, meta }`. Interceptor разворачивает `data`, поэтому в коде фичи работают с чистой сущностью. `meta` (cursor, hasNext) доступна отдельно для пагинированных запросов — не терять её при разворачивании.

### 5.3 Обработка 401 и refresh

- Interceptor реагирует на `401` в двух случаях: код **`TOKEN_EXPIRED`** (обычное истечение) и код **`UNAUTHORIZED` у запроса, ушедшего БЕЗ `Authorization`**. Второй — холодная загрузка страницы: access-токен живёт только в памяти, восстановление идёт в эффекте, и запросы первого рендера успевают уйти раньше. Без этой ветки такой запрос уже не восстановить, и виджет навсегда остаётся с ошибкой. В обоих случаях: один `POST /auth/refresh`, затем повтор оригинального запроса.
- `UNAUTHORIZED` **при наличии** `Authorization` не лечится: токен есть, но сервер его отверг (отозван, сессия погашена) — refresh-cookie в этот момент, как правило, мертва тоже.
- Эндпоинты, которые аутентифицируют сами себя (`/auth/login` и `/auth/login/2fa`, `/auth/refresh`, `/auth/register-by-invite`, `/auth/qr/claim`), из лечения **исключены**: их 401 означает «данные неверны», а повтор второй раз потратил бы лимит попыток входа.
- Обязательна **дедупликация**: параллельные 401 ждут один общий refresh-промис. Иначе десять запросов вызовут десять ротаций токена и разлогин. Это **единственная** точка обмена в приложении — восстановление сессии после перезагрузки идёт через неё же, иначе два параллельных обмена с одной cookie сервер расценит как повторное использование одноразового токена и погасит всю сессию.
- Повторная попытка выполняется **один раз**. Если refresh не удался — `clearAuth()` + редирект на `/login`. Бесконечный цикл refresh → 401 → refresh запрещён.
- `403 FORBIDDEN` → экран/тост «Недостаточно прав». `403 WRONG_SCOPE` → «Ресурс другого университета». Схлопывать эти состояния в одно сообщение не нужно.

### 5.4 Ошибки в UI

- Из interceptor'а наружу пробрасывается `{ code, message }`. Компоненты реагируют на **`code`**, не на текст сообщения.
- Пользователю показывается человекочитаемый текст из i18n по `code`, а не сырой `message` бэкенда и никогда не stack trace.
- Каждый мутирующий запрос имеет обработку ошибки. `.catch(() => {})` — запрещено.
- Показать пользователю экран ошибки — половина работы: исключение обязано уехать в Sentry
  (Ф13.8). Все `error.tsx` — реэкспорт общего `ErrorScreen` из `shared/ui`, который делает
  и то и другое; свою разметку boundary писать не нужно. `global-error.tsx` — последний
  рубеж на случай падения корневого layout.
- DSN не задан (`NEXT_PUBLIC_SENTRY_DSN` пуст) → SDK не инициализируется. Так работают dev
  и e2e; проверок «включён ли трекер» в компонентах быть не должно.
- Что НЕ уходит наружу: тела запросов, cookie, заголовки авторизации, `?token=` из URL и
  из хлебных крошек (включая `data.from`/`data.to` крошки навигации). Реализация —
  `shared/lib/sentry-options.ts` + `scrubSentryEvent` из `@studenthub/shared-config`.
  Тесты `sentry-options.test.ts` — гарантия приватности, ослаблять нельзя.
- Session Replay не подключён сознательно: это запись экрана с чужой перепиской и
  документами. Включение — отдельное решение владельца, с `maskAllText`/`blockAllMedia`.

### 5.5 TanStack Query

- Ключи запросов — фабрики в `entities/<entity>/api/keys.ts`: `postKeys.list(filters)`, `postKeys.detail(id)`. Строковые массивы вручную в компонентах — запрещены.
- Серверные данные не дублируются в Redux. В Redux только `auth` и локальный UI-стейт (модалки, сайдбар).
- После мутации — целевая инвалидация (`invalidateQueries({ queryKey: postKeys.list() })`), не `queryClient.clear()`.
- Ленты и сообщения — `useInfiniteQuery` с cursor из `meta.cursor`. Offset-пагинация на фронте не используется.
- Оптимистичные обновления — для лайков/реакций/прочтения уведомлений; обязателен `onError`-роллбэк.

## 6. Аутентификация на клиенте

```ts
interface AuthState {
  user: User | null
  role: Role | null
  universityId: string | null
  facultyId: string | null
  groupId: string | null
  accessToken: string | null   // только в памяти
}
```

- Access-токен — **только** в Redux (память). `localStorage`, `sessionStorage`, обычная cookie — запрещены.
- При перезагрузке страницы токен восстанавливается через `POST /auth/refresh`. До завершения — глобальный скелетон, не форма логина (иначе авторизованный пользователь увидит мигание `/login`).
- Роль для отображения берётся из Redux; для доступа к данным — всегда проверяется сервером.
- Форма регистрации по инвайту (`features/auth-invite`) содержит **только** имя, пароль, фото. Роль/университет/факультет/группа приходят из `GET /invites/:token/preview` и отображаются read-only. Возможность их изменить в UI — критический баг.
- Logout: `POST /auth/logout` → `clearAuth()` → `queryClient.clear()` → отключение сокета → `router.replace('/login')`. Пропуск очистки кэша React Query — утечка данных между пользователями на общем устройстве.

## 7. Формы

- React Hook Form + `zodResolver` со схемой из `packages/shared-schemas`. Дублирование правил валидации во фронте запрещено.
- Ошибки — на уровне поля, рядом с полем. Один общий тост «Ошибка формы» недостаточен.
- Кнопка submit блокируется на время запроса (`isSubmitting`) — защита от двойной отправки. Особенно критично для регистрации по инвайту (токен одноразовый).
- Серверные ошибки валидации (422 + `details[]`) маппятся на поля через `setError(field, ...)`.
- Все подписи, плейсхолдеры и сообщения — через i18n-ключи.
- Формы с файлами: клиентская проверка размера и типа **до** отправки; серверная проверка при этом не отменяется.

## 8. WebSocket на клиенте

- Одно соединение на приложение, создаётся в клиентском провайдере (`shared/api/socket-provider.tsx`), подключается **после** появления access-токена.
- Соединение живёт в контексте; компоненты подписываются через хук `useSocketEvent(event, handler)` и **обязаны** отписываться в cleanup `useEffect`. Утечка подписок при перемонтировании — типичный баг чата.
- `chat:join` отправляется при открытии чата, `chat:leave` — при закрытии/размонтировании.
- Входящие события не доверяются слепо: полученное сообщение проверяется на принадлежность текущему чату перед вставкой в список.
- Realtime-события синхронизируются с кэшем React Query (`setQueryData`), а не хранятся в отдельном локальном стейте. Иначе после рефетча сообщения «пропадут».
- `typing:start` — не чаще раза в 3 секунды (throttle).
- Обрыв соединения показывается пользователю индикатором; при реконнекте — рефетч истории чата.
- Токен обновился → сокет получает новый токен без разрыва соединения.

## 9. UI, доступность, адаптивность

- Только Tailwind-утилиты и `shadcn/ui`. Произвольные значения (`w-[347px]`) — только когда нет подходящей утилиты.
- Мобильный сценарий — основной: студент открывает расписание с телефона. Верстка проверяется на 375 / 768 / 1280 px.
- Каждое асинхронное состояние имеет три вида: loading (скелетон, не спиннер на весь экран), empty (осмысленный текст + действие), error (сообщение + «Повторить»).
- Изображения — `next/image` с `width`/`height`; `priority` для аватара и первого экрана ленты.
- Списки: `key` — стабильный `id`, не индекс массива.
- Доступность: интерактивные элементы достижимы с клавиатуры, у иконочных кнопок есть `aria-label`, у полей — связанный `<label>`, у модалок — фокус-трап (берётся из `shadcn/ui`).
- `dangerouslySetInnerHTML` — запрещён без санитизации (пользовательский контент в постах и комментариях рендерится как текст).
- Даты форматируются через `date-fns` с активной локалью. Расписание и события — в часовом поясе университета, не браузера.

## 10. i18n

- Языки: `ru` (основной), `kk`, `en`. Fallback: текущий → `ru` → ключ.
- Хардкод пользовательского текста в JSX запрещён — включая заголовки, кнопки, тосты, `alt`, `aria-label`, сообщения ошибок.
  - **Единственное исключение — `app/global-error.tsx`** (Ф13.8): он рендерится вне корневого
    layout, значит вне `NextIntlClientProvider`, и `useTranslations` там бросает. Две строки
    на `ru` (`DEFAULT_LOCALE`) и инлайн-стили (globals.css грузит тот самый упавший layout).
    Расширять исключение на другие файлы нельзя.
- Ключи — dot-notation по фичам: `applications.status.processing`, `auth.invite.expired`. Динамическая сборка ключей (`t(\`auth.${x}\`)`) запрещена.
- Наборы ключей во всех трёх языках идентичны. Отсутствующий ключ — предупреждение сборки.
- Коды ошибок бэкенда переводятся на фронте: `errors.WRONG_SCOPE`. Бэкенд отдаёт код, не готовую строку.
- Множественные числа — ICU-формат (важно для русского: 1 заявка / 2 заявки / 5 заявок).
- Академические термины на русском/казахском не «переводятся» в английский.

## 11. Производительность

- Динамический импорт для чартов, редакторов, календарей, всего, что не в первом экране.
- Barrel-файлы, тянущие весь слой, запрещены — публичные `index.ts` слайсов реэкспортируют только нужное.
- Параллельные независимые запросы — `Promise.all` / несколько `useQuery`, не водопад.
- `prefetch` для критичных переходов (лента → пост, чаты → чат).
- Бандл проверяется через `@next/bundle-analyzer` перед релизом. Рост > 15% требует объяснения в PR.
- Долгие списки (лента, сообщения, список студентов) — виртуализация при > 200 элементов.
- Мемоизация (`useMemo`, `memo`) применяется по факту измеренной проблемы, а не превентивно.

## 12. Тестирование

| Тип | Инструмент | Что покрываем |
|---|---|---|
| Unit / компоненты | Vitest + React Testing Library | Формы и их валидация, ролевой рендер, состояния loading/empty/error |
| Мок API | MSW | Все сетевые ответы в тестах. Ручные моки axios запрещены |
| E2E | Playwright (`apps/web/e2e/`) | Логин, регистрация по инвайту, лента, отправка сообщения, создание заявки |

- Запрос по роли и label (`getByRole`, `getByLabelText`), не по классам и `data-test-id` без необходимости.
- Обязательные негативные сценарии: истёкший инвайт, 403 при чужом маршруте, обрыв сокета, ошибка загрузки файла.
- Именование: `<component>.test.tsx`, `<flow>.e2e.ts`.
- После изменений в UI агент делает скриншот (Playwright) и сверяет с ожидаемым состоянием.
- **Заявление о готовности без запуска `pnpm --filter web lint` и `build` недопустимо.**

## 13. Код-стиль

- Файлы и папки — `kebab-case`: `register-form.tsx`, `invite-preview.query.ts`, `use-notifications.hook.ts`.
- Компоненты — `PascalCase`, один компонент на файл, имя файла соответствует компоненту.
- Props-интерфейс — `<Component>Props`, деструктуризация в сигнатуре функции.
- `any` запрещён; в `catch` — `unknown` + `instanceof`.
- Prettier: без точек с запятой, одинарные кавычки, `printWidth: 100`.
- Никаких `console.log` в коммитах.
- Типы сущностей импортируются из `packages/shared-types`. Локальное переобъявление `interface User` — запрещено.

## 15. Абсолютные запреты

1. Токены (access или refresh) в `localStorage` / `sessionStorage` / обычной cookie.
2. `fetch` или новый axios-инстанс в компоненте, минуя `shared/api`.
3. Хардкод строки, видимой пользователю, вместо i18n-ключа (исключение — `global-error.tsx`, см. §10).
4. Нарушение направления импортов FSD.
5. Дублирование Zod-схемы или типа, уже существующего в `packages/shared-*`.
6. Хранение серверных данных в Redux.
7. Роль или доступ, выведенные из данных ответа вместо `auth`-стейта и матрицы доступа.
8. `dangerouslySetInnerHTML` для пользовательского контента.
9. `key={index}` в динамических списках.
10. Заявление о готовности без запуска линтера и сборки.

## 16. Открытые вопросы к исходной документации

| # | Вопрос | Почему важно |
|---|---|---|
| 1 | В §12.3 указан Redux Toolkit, в §15.3 — React Query. Разделение зон ответственности не описано. | Зафиксировано в этом документе: Redux = auth + UI, React Query = серверные данные. Требует подтверждения. |
| 2 | `middleware.ts` определяет роль по JWT из cookie, но access-токен по §15.4 в cookie не хранится. | Middleware должен читать **refresh**-cookie либо отдельную нечувствительную cookie с ролью. Требует решения до реализации auth. |
| 3 | В §15.1 слой `pages` соседствует с `app/` — нестандартно для Next.js App Router. | Возможен конфликт имён с legacy Pages Router. Рекомендуется переименовать в `views/` или `screens/`. |
| 4 | Часовые пояса расписания не описаны. | Университеты в разных городах/странах (`University.country`). Нужно поле таймзоны у университета. |
| 5 | Сторисы (v2.0) присутствуют в маршрутах ролей v1.0. | Нужно решить: скрывать пункт меню за фича-флагом или убрать из v1.0. |
