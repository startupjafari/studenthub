# StudentHub — лендинг (`apps/landing`)

> Публичный сайт платформы. Отдельное приложение, отдельный домен, **ноль импортов из
> `apps/web`**. Документ описывает, почему так и что из этого следует.
> Версия: 1.2 · Последнее обновление: 2026-11-02

---

## 1. Зачем отдельное приложение

Лендинг не касается платформы по коду. Это несущее решение, а не вкусовое.

| Что даёт | Следствие |
|---|---|
| Нулевой риск для продукта | Маркетинг катит сайт хоть десять раз в день — задеть `apps/web` нечем |
| Разделённые origin | Аналитика и пиксели на сайте не делят домен с refresh-cookie платформы |
| Разный темп | Правка заголовка не требует ревью фронтендера продукта |
| Простой рендер | Страницы статические, без cookie-локали; на клиент уезжает поведение, а не содержимое |

Цена решения — дублирование: токены бренда, тексты и часть разметки живут в двух местах.
Это принято осознанно (§4).

## 2. Домены

```
studenthub.kz          → apps/landing   публичный сайт, индексируется
app.studenthub.kz      → apps/web       вся закрытая часть
api.studenthub.kz      → apps/api       без изменений
```

Лендинг держит **постоянные редиректы** на платформу для всех её корневых сегментов
(`next.config.mjs`, `PLATFORM_SEGMENTS`). Это обязательно, а не удобство:

- `/r/<код>` — QR-наклейки над дверями аудиторий **уже напечатаны** (`PROJECT.md §3.9`),
  перепечатать их нельзя;
- `/c/<код>` — QR-наклейка на экземпляре библиотечной книги, тоже на бумаге;
- `/verify` — код проверки печатается на бланке справки, его открывают банки и посольства;
- `/login`, `/employer/*`, `/legal/*` и закрытые разделы (`/settings` из подвала писем) —
  расходятся по письмам и закладкам; на закрытый раздел middleware платформы сам отправит
  на вход.

Список сегментов сверен с `PUBLIC_PATHS` в `apps/web/src/middleware.ts` и с деревом
`apps/web/src/app/**`. При появлении нового публичного раздела платформы его нужно добавить
и сюда — это единственное место, где лендинг вообще знает о путях продукта.

**Формы на лендинге нет и не планируется.** Заявка вуза на тестирование (`PROJECT.md §31`)
живёт на платформе, `/demo`, а лендинг только ведёт к ней ссылкой. Причина не в экономии:
форма здесь потребовала бы CORS с чужого origin, а персональные данные заявителя оказались
бы в приложении, у которого нет ни аутентификации, ни журнала аудита, ни правил хранения.
Ссылка настроена в `platformLinks().demoRequest` (`src/config/site.ts`), сегмент `demo` — в
редиректах выше. Всего ссылок на платформу четыре, и все собраны там же: `login`,
`demoRequest` (`/demo`), `employerSignup` (`/employer/signup`), `verifyDocument` (`/verify`).
Ссылки на платформу несут язык страницы (`?lang=`): middleware платформы
переносит его в cookie `NEXT_LOCALE`, иначе с казахской версии сайта человек попадал бы
на русский вход.

> **Переезд платформы на поддомен — операция на проде.** Меняются `NEXT_PUBLIC_APP_URL`,
> `CORS_ORIGIN` у api и домен refresh-cookie; все открытые сессии разлогинятся один раз.
> Выполняется человеком, отдельно от выкатки лендинга.

## 3. Граница изоляции

Правило держится линтером, а не договорённостью — в корневом `eslint.config.mjs` для
`apps/landing/**` включён `no-restricted-imports`:

```
**/web/src/**   ../../web/**   @studenthub/*
```

Workspace-пакеты запрещены наравне с кодом: контракт API — тоже связанность. Один
«безобидный» импорт типа заявки потянет за собой остальное.

**Что делать, если из платформы что-то понадобилось:** продублировать у себя. Если дубль
получается большим и живым (не текст, а логика) — это сигнал, что задача решается не там.

## 4. Что дублируется осознанно

| Что | Где | Чем страхуемся |
|---|---|---|
| Токены бренда (цвет, радиус, шрифт) | `src/app/globals.css` | Расхождение видно на снимках продукта рядом на странице |
| Меш-сетка первого экрана | `src/app/globals.css` | Это CSS-правила, а не компоненты |
| Заставка запуска | `src/app/globals.css` + `src/ui/splash.tsx` | То же: CSS-правила и свой компонент на здешней типографике. Тайминги совпадают с платформой намеренно — вход на сайт и вход в приложение должны ощущаться одним движением |
| Тексты | `src/content/*.ts` | Тип `Dictionary` не даёт пропустить поле ни в одном языке |

Общий пакет `packages/brand-tokens` был бы чище копии, но это новая сущность в монорепо —
отдельное решение, не побочный эффект лендинга.

### 4.1 Что уезжает на клиент

Лендинг не «статический» в смысле «ноль JavaScript» — у него есть переключатель ролей и
меню языка. Граница другая: **клиентские только обёртки поведения**, разметка и тексты
остаются серверными.

Приём — `children`: `Reveal` (`src/ui/motion.tsx`) помечен `'use client'`, но принимает
готовую серверную разметку пропсом. Поэтому секции вроде `Doors` или `Security` остаются
серверными компонентами, хотя их карточки анимированы. `Lift` и `TapLink`
(`src/ui/press.tsx`) клиентскими не являются вовсе — отклик на них чисто CSS.
Если вместо этого поставить `'use client'` на сами секции, на клиент поедет вся вёрстка
вместе с текстами — а словарь у нас на три языка.

Первый экран движется на CSS, а не на Framer Motion, и это не исключение по недосмотру:
его анимация обязана идти, пока бандл ещё грузится, иначе LCP ждёт гидрации.

Появление блоков и отклик карточек тоже на CSS — ради 60 кадров на слабом телефоне.
Скрипт только ставит класс (`.is-in` у `Reveal`, один `IntersectionObserver` на страницу),
а переход по `opacity` и `transform` ведёт браузер в потоке композитора, не деля кадр с
прокруткой. Туда же ушли подсветка сетки за курсором (пятно едет трансформом, без
перерисовки) и размытие под шапкой: оно включено только при курсоре, на тач-экранах
шапка почти непрозрачная. Правило для нового движения: только `transform` и `opacity`.

| Зависимость | Зачем | Что было бы без неё |
|---|---|---|
| `framer-motion` | `layoutId` (переезд подложки таба), `AnimatePresence` (смена роли и мобильного меню) | Переезд подложки пришлось бы считать вручную через `offsetLeft/offsetWidth`, а смену содержимого — держать на перезапуске CSS-анимации по `key` |
| `@fontsource-variable/onest` | Дисплейная гарнитура заголовков и логотипа | Заголовки на Inter — он текстовый и на крупном кегле нейтрален |

Про Onest отдельно: он выбран не по вкусу, а по покрытию. Рынок — вузы Казахстана и СНГ,
почти весь читаемый текст кириллический, а у многих модных гротесков (Schibsted Grotesk,
Geist) кириллицы нет вовсе. Такой шрифт даёт молчаливый откат: латиница берётся из него,
кириллица — из запасного, и разницы не видно нигде, кроме логотипа и цифр. **Перед заменой
дисплейной гарнитуры проверьте подсеты** — `api.fontsource.org/v1/fonts/<id>`, поле
`subsets` должно содержать `cyrillic`.

## 5. Языки

Три собранных версии: `/` (ru), `/kk`, `/en`. Никакой cookie-локали — у сайта нет сессии,
а ссылку на язык можно отправить и сохранить.

Отсюда три корневых layout (по одному на route group): `<html lang>` обязан
соответствовать содержимому, а из общего layout его не переопределить. Разметка документа
при этом одна — `src/app/root-shell.tsx`.

Полноту переводов проверяет компилятор: словарь типизирован `Dictionary`. Отдельный тест,
как `shared/i18n/messages.test.ts` в платформе, здесь не нужен.

**Казахский требует вычитки носителем** перед выкаткой в прод.

## 6. Чем показываем продукт

Скриншотов на лендинге нет. От них отказались сознательно: шесть-семь снимков весят
больше всей остальной страницы, устаревают с каждым релизом интерфейса и требуют
поднятой базы с сидом, чтобы их переснять. Вместо них — нарисованный макет рабочего окна,
который перестраивается под роль.

### Макет ролей (`src/ui/scenes/app-mock.tsx`)

Узнаваемый каркас — шапка окна, боковое меню, рабочая область — с настоящими названиями
разделов роли. Переключение роли перестраивает меню и заголовок открытого раздела: именно
это и доказывает тезис секции, что роли видят разное.

Строки содержимого — **полоски**, и это решение, а не заглушка. Ведомость с фамилиями и
оценками пришлось бы выдумать целиком: настоящих студентов на публичной странице быть не
может, а придуманные — это данные, которых не существует, показанные как существующие.
Полоска честно говорит «здесь список» и ничего сверх этого не обещает.

Ширины полосок заданы списком, а не случайным числом: макет рендерится на сервере, и
`Math.random()` дал бы разную разметку на сервере и на клиенте — ошибку гидрации.

### Язык движения

Механика взята из редизайна Seven Hills (`index.html` в корне репозитория) — у команды
уже есть работающий язык движения, и второй заводить незачем. Перенесены приёмы, не
фирменный стиль: цвета, шрифт и тон остаются StudentHub.

| Приём | Где |
|---|---|
| `.sh-reveal` + `.is-in`, каскад через `--d` (`delay` — место в очереди, шаг 70 мс) | все секции, компонент `Reveal` (`src/ui/motion.tsx`) |
| Построчный вход заголовка (`.reveal-line`) | первый экран |
| Шапка уезжает при движении вниз | `.sh-header.is-hidden`, `SiteMotion` |
| Счётчики `data-count` с замедлением к концу | секция «Масштаб», кроме нуля; `SiteMotion` |
| Плавное закрытие вопросов (`<details>` + `.is-closing`) | «Вопросы», `src/ui/accordion-motion.tsx` |

Наблюдатель появления **один на страницу** — общий `IntersectionObserver` на уровне модуля
`src/ui/motion.tsx`, к нему подключается каждый `Reveal`; граница срабатывания — нижние 12 %
окна. Если бы каждая секция заводила свой наблюдатель со своим порогом, блоки всплывали бы
вразнобой. Шапку и счётчики ведёт отдельный `src/ui/site-motion.tsx` (один на страницу, без
разметки). Появление одноразовое (`unobserve` после срабатывания): блок, который уплыл и
приплыл обратно, не должен проявляться заново — это читается как сбой, а не как приём.

Всё отключается при `prefers-reduced-motion`: блоки просто показаны, числа сразу на
конечном значении, шапка не ездит.

Счётчик на нуле не анимируется вовсе: набегать ему неоткуда, и движение от нуля к нулю
читается как сломанный виджет, а не как приём.

### Ритм и симметрия

Один контейнер (`max-w-[88rem]`, поля `clamp(1.25rem, 4vw, 3rem)`), один вертикальный
отступ полосы (`clamp(5rem, 9vw, 9rem)`), одна лестница заголовков — всё задаётся в
`src/ui/primitives.tsx` и только там. Секция со своими отступами ломает выравнивание
всей страницы, поэтому собственных отступов у секций нет.

Фоны чередуются строго, а страница обрамлена двумя брендовыми полосами:

```
первый экран (бренд) → двери → роли → модули → безопасность
→ внедрение → масштаб → вопросы → призыв (бренд) → подвал
```

Тон полосы задаётся пропом `tone` у `Section`, а порядок — в одном месте, в композиции
страницы (`src/ui/landing-page.tsx`). Секция, выбирающая тон сама, рано или поздно
окажется одного цвета с соседней, и полосы перестанут читаться. Тонов два, оба
нейтральные: цвет бренда появляется ровно дважды — на первом экране и на призыве.

Сетки карточек всегда дают полный ряд: три двери — 3 колонки, шесть модулей и шесть пунктов
безопасности — 2×3, четыре шага внедрения — 2×2 или один ряд, четыре числа — 2 или 4.
Карточки тянутся по высоте (`items-stretch` + `h-full`): колонка с коротким текстом,
обрывающаяся выше соседних, читается как ошибка вёрстки.

### Что переиспользовано из платформы

Меш-сетка первого экрана и заставка запуска перенесены **правилами CSS**, а не импортом:
узнаваемость бренда переносится, изоляция не нарушается.

Голографический блик (`sh-holo`) и сканирующая линия (`sh-scan`) жили в сценах «Одного
дня» и удалены вместе с ними: правило CSS без единого владельца — это мёртвый код,
который переживает несколько ревизий, потому что «вдруг пригодится».

### Видео

Отдельным треком, вторым экраном, по клику (постер + фасад). Не автоплеем в шапке: вес
бьёт по LCP, а ролик стареет хуже всего остального.

## 7. Чего на странице не будет

Не «пока нет», а решение:

- логотипов вузов без письменного разрешения;
- придуманных метрик («10 000 студентов уже с нами»);
- отзывов-заглушек и стоковых фотографий;
- цен и тарифов — продажа вузу это разговор, а не корзина;
- блога и CMS.

## 9. Деплой

Отдельный сервис: свой `Dockerfile` и `railway.json`, контекст сборки — корень монорепо
(как у `api` и `web`). Пошагово — `docs/RAILWAY.md §3.1`.

| | |
|---|---|
| Образ | `apps/landing/Dockerfile`, Next в режиме `standalone` |
| Запуск | `node apps/landing/server.js`, порт из `PORT` (в образе 3000) |
| Адрес бинда | `HOSTNAME=::` — dual-stack. Прокси Railway ходит по IPv6, слушатель на `0.0.0.0` даёт 502 при живом процессе |
| Пользователь | непривилегированный `nextjs` — контейнеру, раздающему статику, root не нужен |
| Размер | ≈277 МБ |
| Зависимости | нет: ни базы, ни Redis, ни общего кода с платформой |

Слой зависимостей тоньше, чем у `web`: лендинг не тянет ни одного workspace-пакета, и
кэш этого слоя не сбрасывается от правок в `shared-*`.

**Все `NEXT_PUBLIC_*` инлайнятся на сборке** — их правка требует ре-деплоя, а не
рестарта. `NEXT_PUBLIC_APP_URL` критичен вдвойне: из него строятся и кнопки «Войти», и
308-редиректы, а на них завязаны напечатанные QR-наклейки над дверями аудиторий.

Для самостоятельного хостинга сервис `landing` добавлен в
`docker/prod/compose.yml`, маршрут к нему — в
`docker/prod/nginx/templates/default.conf.template`: корневой домен (и `www.`) ведёт на `landing`,
`app.<домен>` — на платформу. Сами имена задаются переменными `SH_DOMAIN` и `SH_APP_DOMAIN`
в `docker/prod/.env`, править конфиг nginx для этого не нужно.

## 10. Команды

```bash
pnpm --filter landing dev          # :3002
pnpm --filter landing build
pnpm --filter landing start        # собранное, :3002 (корневой `pnpm start` поднимает его вместе с остальными)
pnpm --filter landing lint
pnpm --filter landing typecheck
```

Переменные окружения:

| Переменная | Значение | Без неё |
|---|---|---|
| `NEXT_PUBLIC_APP_URL` | адрес платформы (`https://app.studenthub.kz`) | `http://localhost:3000` |
| `NEXT_PUBLIC_SITE_URL` | адрес самого лендинга — для canonical, sitemap и OG | `http://localhost:3002` |
| `NEXT_PUBLIC_SALES_EMAIL` | почта рядом с призывом — для тех, кто хочет поговорить, а не заполнять форму | `hello@studenthub.app` (пустая строка из незаданного build-arg тоже даёт умолчание) |

Адреса можно задавать голым доменом, как его отдаёт хостинг (`RAILWAY_PUBLIC_DOMAIN`):
схему `https://` и срез хвостового слэша добавляет `normalizeOrigin` — в
`src/config/site.ts` и его намеренный дубль в `next.config.mjs` (конфиг Next не может
импортировать TypeScript). Правка одного требует правки второго.
