# Выпуск приложения для iPhone

Что нужно сделать человеку, чтобы сборка дошла до TestFlight, и что уже сделано в
репозитории. Документ дополняет `docs/RELEASE.md` (релизы платформы) и не заменяет его:
версия приложения живёт отдельно от версии веба и бэкенда.

## Что уже готово в репозитории

- `apps/ios/project.yml` — проект генерируется XcodeGen, подпись автоматическая,
  `MARKETING_VERSION` и `CURRENT_PROJECT_VERSION` заданы явно;
- `apps/ios/Config/Release.xcconfig` — адрес боевого API (**подставить домен Railway**,
  сейчас стоит заглушка `api.example.invalid`, чтобы его нельзя было забыть);
- `apps/ios/Config/ExportOptions.plist` — параметры экспорта архива в App Store Connect;
- `apps/ios/Resources/PrivacyInfo.xcprivacy` — манифест приватности, сверен с
  `docs/PERSONAL_DATA.md`;
- `.github/workflows/ios-release.yml` — ручной прогон: архив и загрузка в TestFlight.
- `.github/workflows/ios.yml` — сборка и тесты на симуляторе на каждый push и PR в
  `develop`/`main`, задевающий `apps/ios/**`.

## Что открыто до выпуска

Непроверенное и незакреплённое до TestFlight и App Store (`docs/IOS_RULES.md` 15.7.8).
Отладочная копия с устройства (`apps/ios/README.md`, «Чем отладочная копия отличается…»)
этого не покрывает.

- **Адрес боевого API.** В `apps/ios/Config/Release.xcconfig` — заглушка
  `api.example.invalid`; подставить домен до первого архива.
- **Версии пакетов SPM не закреплены.** GRDB, Socket.IO и Sentry объявлены через `from:`,
  `Package.resolved` в `.gitignore` (`apps/ios/.gitignore`, комментарий в `project.yml`) —
  CI и релиз берут свежий минор. Закреплять ли — открытый вопрос, решение владельца
  (`docs/IOS_RULES.md` 14.1.2).
- **Пуши не проверены.** Отладочная копия на личном Apple ID не подписывает
  `aps-environment`; доставку проверить на первой сборке из TestFlight с ключом APNs.
- **Sentry не проверен.** В отладке `SENTRY_DSN` пуст; на сборке из TestFlight проверить,
  что события доходят, а сетевые крошки без адресов (`docs/IOS_RULES.md` 10.2.8).
- **Иконка.** В каталоге одна картинка 1024×1024
  (`apps/ios/Resources/Assets.xcassets/AppIcon.appiconset`); сверить, что загрузка в App
  Store Connect её принимает.
- **Подпись распространения и Release-сборка.** Проверяются только прогоном
  `ios-release.yml`; собирать ли Release на каждый PR — решение владельца
  (`docs/IOS_RULES.md` 4.1.2).

## Что обязан сделать человек

Это нельзя сделать из репозитория — всё требует учётной записи Apple.

1. **Apple Developer Program** — 99 $ в год, на организацию (не на личный Apple ID:
   приложение университетской платформы должно принадлежать компании).
2. **App ID** `kz.studenthub.app` и запись приложения в App Store Connect.
3. **Сертификат распространения и профиль** либо включённая автоматическая подпись с
   ключом App Store Connect API (рекомендуется для CI).
4. **Секреты репозитория** для `ios-release.yml`:
   - `APPSTORE_ISSUER_ID`, `APPSTORE_KEY_ID`, `APPSTORE_PRIVATE_KEY` — ключ App Store
     Connect API (роль App Manager);
   - `IOS_TEAM_ID` — идентификатор команды.
5. **Ключ APNs (p8)** и переменные `APNS_*` на бэкенде — без них пуши молчат
   (`docs/PROJECT.md` §8.3 «Пуши на устройства»).
   Там же — `IOS_MIN_SUPPORTED_VERSION` и `IOS_STORE_URL` (`docs/PROJECT.md` §8.3 «Версия
   мобильного клиента»): планка версии, ниже которой приложение просит обновиться
   (по умолчанию `0.0.0` — не блокируется никто), и ссылка для кнопки «Обновить».
6. **App Privacy labels** в App Store Connect — заполняются руками по тем же данным,
   что перечислены в `PrivacyInfo.xcprivacy`: имя, email, идентификатор пользователя,
   фото и видео, аудио, содержимое переписки, точная геопозиция (отправка точки и живая
   трансляция в чат), контакты (карточка контакта, которую человек сам отправил),
   диагностика. Отслеживания нет.

   **Фоновая геопозиция.** В `UIBackgroundModes` есть `location`: живая трансляция в
   чате продолжается свёрнутой, с синим индикатором системы, только по явному включению
   человеком и на выбранный срок (15 мин / 1 ч / 8 ч). В заметках для ревью это надо
   написать прямо и показать путь: чат → скрепка → «Геопозиция» → «Транслировать
   геопозицию». Разрешение — «при использовании», «всегда» не запрашивается.
7. **Демо-аккаунт для ревью** (см. ниже) и заметки к версии.

## Демо-аккаунт для ревью Apple

Проверяющему нужен вход без приглашения и без 2FA — иначе приложение отклонят с
формулировкой «не удалось войти». Требования к учётной записи:

- роль `STUDENT` в показательном вузе (не в боевом вузе-клиенте);
- 2FA выключена, пароль не истекает;
- в группе есть расписание, пара на ближайшие дни, хотя бы один чат с перепиской,
  одно задание и один материал — пустые экраны ревью читает как неработающие;
- аккаунт не удаляется между релизами: Apple проверяет каждую сборку.

В заметке для ревью (App Review Information) указываются логин, пароль и строка:
«Закрытая платформа университета, регистрация только по приглашению вуза. Для проверки
используйте демонстрационную учётную запись».

## Заметки к версии

Шаблон для TestFlight («Что тестировать»):

```
Версия X.Y.Z
— что появилось (списком, по одной строке на изменение);
— что чинилось;
— на что обратить внимание при проверке.
```

История версий приложения ведётся здесь же, рядом с `docs/RELEASE.md`, и не смешивается
с релизами веба: пользователь обновляет их независимо.
